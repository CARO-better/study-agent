## 图片问题：根因与修复

旧实现不是按原文件字节数拒绝，而是要求压缩后的图片 Base64 不超过 64,000 字符，并检查完整请求不超过 90,000 UTF-8 字节。压缩只限制宽度：

- 窄而长的截图在宽度已经较小时不会继续缩小，像素总量仍可能很大。
- 微信文档说明 `quality` 只对 JPG 生效；iOS 的 `compressImage` 仅支持 JPG。PNG 截图无法依赖质量参数降低体积。
- 因此原文件较小但内容复杂、格式为 PNG 或比例很长的图片，可能比更大的 JPG 照片占用更多 Base64 字符。原文件 MB 数不能单独决定是否通过。

新实现：

- 按宽高两条边的最长边计算目标尺寸，不再只限宽。
- JPG 使用 `compressImage`，按 1440/1080/800/640 长边与 78/55/65/50/42 质量逐级尝试。
- PNG 和未知格式使用 2D Canvas 重绘到最长 1440px，再编码为 JPEG；压缩接口仅作为回退。
- 小文件仍先读取实际 Base64；不会因文件小就跳过预算检查。
- 超限提示包含原格式和压缩后实际字符数，明确要求裁剪文字区域；发送前超限不会清空输入或附件。

## 消息气泡

- AI 的 Markdown 与纯文本回复共用同一个圆角气泡外壳：用户气泡右下收角，AI 气泡左下收角，保留不同底色与对齐来区分角色。
- Markdown 排版覆盖移入 `miniprogram/towxml/assistant-overrides.wxss`，由 Towxml 自己的样式表在主题样式之后引入。原因是外层页面/组件样式不能稳定穿透 Towxml 的组件边界；仅靠 `.rich .h2w...` 会出现内部不透明方底、绿色链接和主题色未覆盖。
- 保留标题、列表、引用、链接、行内代码、代码块与表格；表格在气泡内部横向滚动。
- AI 消息出现后，空态欢迎层不再占位；`hasMessages` 作为显式视图状态，并由线程非空回归保护。

## 弹层转场与材质

- AI 浮层记录圆钮与面板的几何关系，从左上圆钮缩放展开，关闭时缩回同一位置。
- 模型设置从助手右上设置入口进入，退场回该入口。
- 任务/课程、消息、同步、资源弹层把点击坐标写入 `sheetOrigin`，以该位置作为横向缩放入口和返回点。
- 引入 `assistantClosing`、`settingsClosing`、`closingSheet` 等关闭阶段；退场期间节点保持挂载，动画结束后才卸载。
- 编辑页退场使用关闭令牌；在 220ms 退场期间重新打开记录会清除旧定时器，不会让上一次关闭把新草稿误关掉。
- AI 关闭一开始就调用 `beginClose` 标记控制器销毁，延迟工具不再写入或更新界面，不等动画结束。
- 关闭动效时走零时长路径，不播放空间位移。
- 浮层统一使用现有 `--glass`、`--veil`、圆角、边缘高光和阴影变量；没有引入新的动画库或 WebGL。
