## 建议试用顺序

1. 在「课程」新增课程，填写学期名称。
2. 在「今日」新增任务，选择课程、任务类型、截止日期、预计用时和优先级。
3. 在「计划」添加未来的可用日期及开始、结束时间，再点击生成计划。
4. 试着锁定安排后重新生成，或撤销上一次生成。
5. 返回任务切换完成状态，再生成一次计划，观察变化。
6. **杀掉小程序重进**，确认数据还在（本地 + 云端拉取）。
7. **在微信「设置 → 通用 → 存储空间」清理本小程序缓存**，重新打开，确认数据自动恢复并出现「已从云端恢复数据」提示。

第 6、7 步是验证云同步是否真的生效的关键，第一次升级后建议走一遍。

## 设置页的四个云端按钮

| 按钮 | 作用 | 何时用 |
| --- | --- | --- |
| 检测云端连接 | 报运行时版本、集合可读性 | 排查云函数部署 / 集合缺失 |
| 预览上云内容（不上传） | 转换本地数据并列出必须先解决的问题 | 首次迁移前确认 |
| 上传到云端 | 确认后按 学期→课程→任务 顺序上传 | 首次迁移，或快照同步异常时的兜底 |
| 从云端恢复（清缓存后用） | 拉回云端数据覆盖本地 | 自动恢复失效时的手动兜底 |

日常使用**不需要点这些按钮**，同步是自动的。

## 数据与限制

**同步机制**：云端 `snapshots` 集合里每个用户固定一条记录，内容是完整 store 的 JSON。整份覆盖而非逐条同步，避免本地 id 与云端 `randomUUID` 两套体系对齐时静默丢数据。

**已知限制**：

- **多设备交替编辑会互相覆盖**（按 `updatedAt` 后写胜，无字段级合并）。
- 改完立刻强杀进程，最后 800ms 内的改动可能来不及推送。
- 「从云端恢复」是**覆盖式**的，本地较新的内容会被丢弃；执行前有确认弹窗。
- 模型 Key 加密存云端后，主密钥 `STUDY_MASTER_KEY` 一旦丢失或更换，已存的 Key 解不开，需要删掉重填。
- 清理微信缓存前不必再手动上传，但**换手机时建议先确认云端快照是最新的**（打开小程序看到数据即说明已同步）。

**删除行为**：删除课程会保留原任务并解除课程关联；删除任务会移除对应当前计划块。删除需要确认。

**时区**：任务和可用时间按设备本地时区录入，请使用北京时间系统设置。
