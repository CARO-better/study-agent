## 3. 当前架构

### 3.1 数据流

```
本地 store (wx.getStorageSync 'study_trial_v1')
   │
   ├─ 任何改动 → save() → 立刻写本地 + sync.schedule() → 800ms 后整份推到云端
   │
   └─ 启动 onLoad → 先用本地渲染（不等网络）
                    → 异步 sync.pull()
                    → sync.decide() 判断用谁
                    → 云端更新则覆盖本地
```

**云端不参与实时读写**，只是「整份快照的备份」。这样做避免了两套 id 体系（本地 `uid()` vs 后端 `randomUUID`）对齐的复杂度。

### 3.2 AI 调用链

```
AI 页 send()
  → ai.runAgent()（前端跑 tool 循环，工具操作本地 store）
    → ai.requestModel()
       ├─ 云端可用 → cloud.call('ai.chat') → 云函数解密 Key → 请求模型
       └─ 云端未配模型且本地有 Key → requestModelDirect()（老路径，wx.request）
```

**为什么循环留在前端**：工具（`lib/tools.js`）操作的是本地 store。若把循环搬到云函数，工具就得改成操作云数据库，
是另一套模型，改动量远大于收益。

### 3.3 本地存储键

| 键 | 内容 | 上云 |
|---|---|---|
| `study_trial_v1` | 课程 / 任务 / 排期 | ✅ 快照同步 |
| `study_ai_v1` | 模型设置（含明文 Key，仅未上云时用） | ✅ Key 加密存 `providerSettings` |
| `study_inbox_v1` | 站内消息 | ❌ 不上云，重新生成 |
| `study_sync_stamp_v1` | 本地最后同步时间戳 | — |
| `study_cloud_migrated_at` | 一次性迁移完成时间 | — |

## 4. 关键设计决策（连同理由，别轻易推翻）

**① 同步用整份快照，不做逐条记录同步**
后端 `core/records.js:64` 用 `deps.newId()`（randomUUID）生成 id，`select()` 白名单会丢弃前端 id。
逐条同步需维护 id 映射表 + 删除队列 + 逐条版本比对，任一处错都**静默丢数据**。
代价：多设备同时改会互相覆盖（按 `updatedAt` 后写胜）。已写入文档作为已知限制。

**② 推送成功后用服务端 `updatedAt` 回写本地戳**
手机时钟不准会导致 `decide()` 判断错位。

**③ 本地一改就立刻 markLocal**
否则 800ms 窗口期内若发生 pull，会被云端旧数据覆盖。

**④ `ai.chat` 不复用 `adapters/model.js` 的 `callModel`**
后者强制 `response_format: json_object` + schema 校验，只适合结构化抽取；对话和 tool_calls 必须自由格式。

**⑤ 云端优先 + 本地降级**
只有 `PROVIDER_UNCONFIGURED` / `MASTER_KEY_MISSING` 且本地有 Key 才降级；
`MODEL_FAILED` 等直接抛，避免把「模型坏了」伪装成「没配置」。

**⑥ 集合 12 个，不建 `credentials`**
`credentials` 在代码里引用 0 次，`COLLECTIONS` 白名单也没有；API Key 加密存在 `providerSettings.keyEnvelope`。

## 5. 已知的坑（这次踩过，别再踩）

### 环境坑

| 现象 | 原因与对策 |
|---|---|
| `npm run check-config` 报 `{"missing":["envId","appId"]}` | 它默认读 `deployment/config.example.json` 空模板，**不读** `miniprogram/config.js`。不是没填上 |
| 「请在编辑器云函数根目录选择一个云环境」 | `cloudfunctionRoot` 只管「哪个目录」，**环境绑定不在任何 JSON 里**。先点顶部「云开发」按钮，再右键 `cloudfunctions` → 更多设置 → 选环境，目录出现小云朵才算成功 |
| 云函数 `INTERNAL / 服务暂时不可用` | 云函数把所有内部异常压成 INTERNAL。先调 `system.ping` 看 `bootReport().steps` 哪一步 FAIL |
| 读得到、写不进（`list` 成功 `create` 失败） | **`ownerLocks` 集合不存在**。`transaction()` 每次写都要写它做并发闸门 |
| 部署后运行失败 | 运行时必须 ≥ Node 17：`adapters/repository.js:5` 用了 `structuredClone`，`list` 对每条结果都调它 |
| 微信开发者工具 CLI 调不通 | 服务端口关闭（`设置 → 安全设置 → 服务端口`）。**不要擅自改这个安全设置**，让用户自己开 |
| Bash 工具的 PATH 会丢 | 每条命令先 `export PATH="/c/Users/luojiahao/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:...:$PATH"` |
| PowerShell 工具本机无输出 | 返回 exit 0 但 stdout 为空，不可用，改用 Bash |
| Windows 原生程序（Edge）不认 `/c/xxx` 路径 | 截图等输出必须写 `C:/Users/...` |
| Python 写 `/tmp` 变成 `C:\tmp` | 用 `tempfile.gettempdir()` |
