# 需要你（用户）自己填的内容

更新时间：2026-11-04（北京时间）。这份清单只列**必须由你本人提供、Agent 无法代为获取**的东西。
所有值都不要写进仓库、不要发到聊天里；按下面的位置填到本机文件或云开发控制台即可。

## 0. 先建云环境（这一步不用填任何密钥）

没有云环境，后面所有云端能力都无法开始。两条路，选一条即可：

**路线 A：在微信开发者工具里建（推荐，最少跳转）**

1. 打开微信开发者工具，用小程序管理员微信扫码登录。
2. 「导入」本项目根目录 `D:\study-agent`，AppID 填你自己的（测试号/游客模式不支持云开发）。
3. 点左侧工具栏的「云开发」按钮（云朵图标）。
4. 首次点击会引导开通：同意《微信云开发服务条款》→ 选择套餐/免费额度 → 创建环境。
5. 环境名称随便填（例如 `study-agent`），地域选离你近的（上海/广州）。
6. 创建完成后，控制台顶部会显示**环境 ID**，形如 `study-agent-9g8xxxxx`，复制它。
7. 把环境 ID 填进 `miniprogram/config.js` 的 `envId`，保存、重新编译。

**注意事项**

- 官方文档写明：AppID 首次开通云环境后，**约 10 分钟**云 API 才可用；这段时间调用会报 `cloud init error: invalid scope`，不是代码问题。
- 套餐与计费以控制台页面为准，代码里不会自动购买任何套餐，也不会开启自动续费。
- 一个 AppID 默认可以创建有限个环境；环境之间数据完全隔离，别在不同环境之间混用数据。

**路线 B：在腾讯云控制台建，再接到微信**

1. `console.cloud.tencent.com/tcb` → 新建环境 → 选个人版/免费额度 → 选地域 → 创建。
2. 复制环境 ID。
3. 回到微信云开发控制台 → 设置 → 环境设置 → 「管理我的环境」→「使用已有腾讯云环境」，选中刚建的环境。
4. 同样把环境 ID 填进 `miniprogram/config.js`。

## 1. 云端基础（做云同步/提醒/OCR 的前提）

| 项 | 填到哪 | 说明 |
| --- | --- | --- |
| CloudBase 环境 ID | 云函数环境变量 `STUDY_CLOUD_ENV_ID` | 形如 `study-agent-9gxxxxxx`，在云开发控制台「环境」里看 |
| 存储文件前缀 | 云函数环境变量 `STUDY_CLOUD_FILE_PREFIX` | 形如 `cloud://study-agent-9gxxxxxx.7373-study-agent-9gxxxxxx-13xxxxxxxxx`，必须与真实 fileID 前缀一致 |
| 加密主密钥 | 云函数环境变量 `STUDY_MASTER_KEY` | 32 字节随机数的 base64。生成命令见下方，**生成后自己保存好，丢失会导致已存的模型 Key 无法解密** |

生成主密钥（本机终端执行，结果只保存到云函数环境变量，不要提交）：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## 2. 模型服务（你自选，填在小程序里，不写代码）

在小程序「设置 → 模型」里填，服务端用 AES-256-GCM 加密保存、只回显掩码：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 服务地址 | `https://api.deepseek.com/chat/completions` | 必须是公网 HTTPS、不能带账号密码或查询参数 |
| 模型名 | `deepseek-chat` | 该服务商文档里的模型标识 |
| API Key | `sk-...` | 只有你自己有；接口不会回读明文 |

**不需要你填**：加密逻辑、调用逻辑、用量上限（默认 30 次/天，可在环境变量 `STUDY_DAILY_CALL_LIMIT` 调整）。

## 3. 截图识别（腾讯云 OCR，独立于模型 Key）

填到云函数环境变量：

| 变量 | 说明 |
| --- | --- |
| `STUDY_OCR_SECRET_ID` | 腾讯云访问密钥 SecretId |
| `STUDY_OCR_SECRET_KEY` | 腾讯云访问密钥 SecretKey（**这是密钥，绝不能提交**） |
| `STUDY_OCR_REGION` | 可选，默认 `ap-guangzhou` |
| `STUDY_OCR_DAILY_LIMIT` | 可选，每日识别次数上限，默认 20、最多 60 |

注意：文本模型的 Key 不包含 OCR 能力，这是两笔独立配置、独立计费。

## 4. 微信每日提醒（当前唯一硬前提在模板）

**先说结论：个人主体的小程序拿不到「长期订阅」。** 微信开放社区与官方文档的口径一致：长期订阅只对政务民生、医疗、交通、金融、教育等特定二级行业类目开放，且只支持企业/非个人主体；个人主体只能使用**一次性订阅**。后台「订阅消息 → 公共模板库 → 长期订阅」里如果看不到入口，就是不符合条件，不是漏申请。

| 方案 | 能否做到"连续多天不打开也每天推" | 适配你的情况 |
| --- | --- | --- |
| 长期订阅 | 能 | **不可用**（个人主体） |
| 一次性订阅 | 不能。用户授权一次 = 一条下发机会 | 唯一可行，需要"攒授权" |
| 公众号模板消息 | 能 | 需要服务号，个人主体开不了 |
| 邮件/短信 | 能 | 你已明确拒绝邮件 |

因此提醒功能将按**一次性订阅**实现，产品承诺相应调整为：

1. 用户在你指定的时机（例如打开「今日」页或点「开启提醒」）完成订阅授权，每次授权对应一条可下发额度。
2. 服务端记录每个用户每个模板的剩余额度：发送成功扣 1，额度为 0 时不发送，也不再重试，避免"假装推送"。
3. 额度不足时，界面明确提示"点一次继续接收明日提醒"，而不是静默失败。
4. 每日 08:00—23:00 窗口、每任务每天最多 2 次、完成任务不再提醒，这些规则照旧由服务端判断。

| 项 | 填到哪 | 说明 |
| --- | --- | --- |
| 订阅消息模板 ID | 云函数环境变量 `STUDY_WECHAT_TEMPLATE_ID` | 小程序后台「功能 → 订阅消息」里选一个一次性模板，复制模板 ID |
| 模板字段映射 | 云函数环境变量 `STUDY_WECHAT_FIELD_MAP` | JSON，例如 `{"thing1":"title","time2":"dueText"}`，左边是模板字段名、右边是我们的变量名 |

模板字段名必须和你在后台选的那个模板完全一致（thing1 / time2 / phrase3 这类），拿错会返回 `errcode 47003`。

## 5. B 站检索（默认可匿名，可能被风控）

| 情况 | 你要做的 |
| --- | --- |
| 匿名可用 | 什么都不用填 |
| 返回 `-412`/风控 | 浏览器登录 B 站，复制 Cookie 填到云函数环境变量 `STUDY_BILI_COOKIE` |

检索失败时接口会明确返回 `BILI_UNAVAILABLE`，**不会生成似是而非的链接**。

## 6. 定时触发（提醒与清理的调度）

在云开发控制台给 `api` 云函数添加定时触发器，或在部署时使用 `deployment/triggers.json`。
调度频率建议每 30 分钟一次；真正的发送窗口、每任务每日上限、幂等去重由代码判断，不依赖触发器频率。

## 7. 数据库与权限

按 `deployment/database.json` 建集合与索引，按 `deployment/security-rules.json` 配权限。
这些是控制台里的手动操作，Agent 无法代点；漏配的表现是"接口报错但没有明确原因"。
